# 阶段 7：响应式设计 + UI

[返回路线](../README.md)

## 目标

让同一组业务操作在手机、键盘和桌面上都能完成。

## 阅读入口

[布局样式](../taskboard/app/globals.css)、[浏览器测试](../taskboard/e2e/board.spec.ts)

## 核心概念

桌面看板是三列 Grid；手机改成单列。侧栏隐藏后仍保留阶段筛选。颜色只是辅助表达，文字、标签、焦点和状态消息承担真正的信息传递。

## 动手练习

1. 在 390×844 与 1280×900 检查页面，保存截图。
2. 使用超长邮箱和 120 字符标题，确认不挤出视口。
3. 只使用键盘完成新增和编辑；在慢速网络下观察加载、禁用与错误反馈。

## 运行入口

以下从仓库根目录开始；如命令需要已启动的服务，先按项目 README 启动。

```bash
cd 07-fullstack/taskboard
npm run build
npm run test:e2e
```

## 验收

- [ ] 没有水平滚动，表单标签清楚，任务状态无需仅靠颜色识别。
- [ ] 键盘焦点可见，状态变更通过 aria-live 提示。
- [ ] npm run test:e2e 的移动端用例通过，并人工检查两种尺寸截图。

## 常见误区

不要为截图隐藏真实错误状态；不要把固定桌面宽度直接缩放成手机页面。

把实际结果记入 [练习记录](../practice-log.md)。
