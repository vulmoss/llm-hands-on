# 阶段 16：部署 + 监控 + 扩展

[返回路线](../README.md)

## 目标

交付可运行、可观察、可备份和可恢复的版本。

## 阅读入口

[操作手册](../taskboard/OPERATIONS.md)、[部署 CI](../../.github/workflows/fullstack.yml)

## 核心概念

上线不是命令返回成功：需要健康检查、日志定位、备份恢复与版本回退。APP_ORIGIN 应设为真实 HTTPS 站点来源，反向代理负责 TLS；运行目录必须具备持久磁盘。扩容前先定位瓶颈。

## 动手练习

1. 在 Docker 启动后运行健康检查和冒烟脚本，并记录版本。
2. 创建备份，在新的数据库文件上验证恢复；不要覆盖唯一一份工作数据。
3. 为不可用、5xx 比例、请求延迟、磁盘空间定义告警阈值，并写出从单机迁移到 PostgreSQL 多实例的触发条件。

## 运行入口

以下从仓库根目录开始；如命令需要已启动的服务，先按项目 README 启动。

```bash
cd 07-fullstack/taskboard
curl --fail http://127.0.0.1:3000/api/health
node scripts/smoke.mjs
npm run db:backup
```

## 验收

- [ ] 有发布版本、健康检查输出、关联 requestId 的日志，以及恢复演练记录。
- [ ] 知道备份覆盖账号与会话信息，需要访问控制和保留策略。
- [ ] 没有把“写了 Dockerfile”或“设计了扩容方案”说成已经完成生产部署。

## 常见误区

SQLite 文件不能依赖会被回收的临时磁盘；不要在没有容量测量时直接横向复制服务。

把实际结果记入 [练习记录](../practice-log.md)。
