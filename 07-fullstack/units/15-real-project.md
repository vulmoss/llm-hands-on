## 目标

把一次需求贯穿 UI、API、数据库、测试与文档。

## 阅读入口

[看板项目](../taskboard/README.md)、[原有 LLM API](../../src/llm_lab/api.py)、[验收记录](../practice-log.md)

## 核心概念

当前看板就是第一个完整项目。第二次迭代只选一项需求，先写用户故事和验收条件，再改代码。工作量用可完成的行为衡量，不用技术名词数量衡量。

## 动手练习

1. 基础选项：新增任务截止日期，覆盖创建、编辑、排序、SQL 迁移、权限和测试。
2. LLM 选项：增加“生成复习建议”，由服务端固定地址调用现有 LLM API；增加超时、不可用提示和纯文本渲染，不向浏览器泄漏配置。
3. 为选择的需求创建一个 PR，包含成功/失败路径、截图、测试结果和回滚方式。

## 运行入口

以下从仓库根目录开始；如命令需要已启动的服务，先按项目 README 启动。

```bash
cd 07-fullstack/taskboard
npm run check
npm run test:e2e
```

## 验收

- [ ] 新账号可以从头完成整个功能，不依赖手动修改数据库。
- [ ] 已有账号升级后数据仍可用，其他用户数据不可见。
- [ ] LLM 扩展即使上游不可用，原有任务管理仍可正常运行。

## 常见误区

一次 PR 不要同时替换框架、数据库和认证方式；先让一项功能完整落地。

把实际结果记入 [练习记录](../practice-log.md)。
