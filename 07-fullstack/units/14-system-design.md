# 阶段 14：系统设计

[返回路线](../README.md)

## 目标

从真实限制推导设计，而不是先画很多服务。

## 阅读入口

[架构与边界](../taskboard/ARCHITECTURE.md)、[服务操作手册](../taskboard/OPERATIONS.md)

## 核心概念

先明确请求量、数据量、延迟、恢复时间和成本预算。本项目采用单进程应用和单机数据库；这种选择减少初学者必须同时调试的边界，也意味着无法直接水平扩容。

## 动手练习

1. 画出新增任务的数据流，包括失败分支与会话读取。
2. 假设任务数从 100 增长到 100 万，先分析分页、索引和响应体大小，再讨论服务拆分。
3. 写一页 ADR：如果新增多实例部署，如何迁移 PostgreSQL、会话与限流、备份和数据库迁移。

## 运行入口

以下从仓库根目录开始；如命令需要已启动的服务，先按项目 README 启动。

```bash
cd 07-fullstack/taskboard
node scripts/smoke.mjs
# 在已启动的服务日志中观察 durationMs 与状态码
```

## 验收

- [ ] 每个设计决定都有需求、替代方案和代价。
- [ ] 明确哪些组件目前存在，哪些只是扩展计划。
- [ ] 能够解释为什么加一个负载均衡器并不能解决多个本地 SQLite 副本之间的数据一致性。

## 常见误区

没有测量就引入缓存，可能先引入一致性和排障问题。

把实际结果记入 [练习记录](../practice-log.md)。
