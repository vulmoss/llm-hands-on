# 验证记录

本地验证环境：2026-09-22，macOS arm64，Node 26.8.1，npm 11.19.0。
推荐复现环境为 Node 24 LTS；Node 24 与 Docker 的 Linux 验证由
[fullstack 工作流](https://github.com/vulmoss/llm-hands-on/actions/workflows/fullstack.yml) 执行，以对应提交的实际运行记录为准。

| 检查              | 实际验证内容                                                   |
| ----------------- | -------------------------------------------------------------- |
| npm run typecheck | 客户端、服务端、测试配置的严格类型检查                         |
| npm test          | 8 个测试组：纯函数、密码哈希、真实 SQLite 与 API 处理函数      |
| npm run build     | Next.js 生产构建与 standalone 产物生成                         |
| npm run test:e2e  | 2 个 Chromium 流程，使用生产构建与真实 HTTP                    |
| 数据持久化        | 关闭并重新打开数据库文件后，任务与会话仍可读取                 |
| 账号隔离          | 第二账号无法列表读取、修改、删除第一账号的任务                 |
| 输入与会话        | 400 / 401 / 403 / 404 / 409 / 413 / 415 / 429 路径、过期、撤销 |
| 响应式            | 1280px 桌面、390px 手机截图人工查看，手机无横向溢出            |

浏览器流程覆盖：注册 → 创建任务 → 编辑 → 完成 → 刷新 → 退出 → 重新登录 → 删除。
第二流程验证移动端与 HTML 字符串作为文本渲染。截图与失败 trace 在 test-results 中；
仓库中的 preview.png 是本地实测登录页截图。

本机未安装 Docker。CI 单独构建镜像，验证健康检查、真实 HTTP、重启后任务和会话保持、
运行镜像内的 SQLite 备份。CI 还重新执行 Node 24 下的类型检查、测试、构建与 Chromium 流程。

没有执行生产负载、跨地域可用性、邮箱验证或真实模型效果评估；项目也没有部署到公网服务。
不要将这些离线 / 本地 / CI 结果解释为生产容量与完整安全评估。
