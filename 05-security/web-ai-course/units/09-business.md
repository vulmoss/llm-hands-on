# 09 · 业务状态机、价格、重放与并发

目标：从流程不变量出发设计测试。先修：单元 05。

```bash
python3 -m llm_lab.web_security run --lab business-logic
```

`POST /checkout` 的负数量与客户端价格在漏洞版产生 -1 分，修复版拒绝；数量 2 正常应为 200 分。再试 quantity=1、unit_price=1：修复版仍按服务端价格给出 100 分。这里不下单、不收费，影响只能写“结算计算逻辑接受不可信参数”。

建立状态机：购物车 → 待支付 → 支付中 → 已支付 → 已交付 → 已退款。每条转移写主体、前置状态、资源与不变量。金额不能由客户端决定；退款不能超过已付金额；相同支付通知不能重复履约。

并发不是循环请求的同义词。当前教学服务器用锁串行处理，所以没有声称复现竞态。高级作业在独立测试数据上让两个线程在同一屏障后消费同一库存，观察读后写的丢失更新，再改为原子条件更新或唯一约束，要求高并发下成功次数等于库存。

| 场景 | 资源与主体 | 不变量 |
|---|---|---|
| 物流 | 发件人/收件人/运单 | 他人不能批量导出地址 |
| 云企业 | 租户/子账号/任务 | 租户身份必须作用于每次查询 |
| 企业内部 | 员工/部门/审批单 | 不能跳过审批状态或伪造审批人 |
| 无账号 | 访客/订单分享链接 | 匿名能力仅覆盖设计的对象与期限 |
| 开发者平台 | 项目/成员/API token | token scope 与项目成员权限一致 |

产物：上述场景任选一张矩阵、价格反例、状态转移图、幂等与并发的明确验收条件。验证码只用合成计数器学习过期、一次性、次数限制，不向真实电话/邮箱发送请求。
