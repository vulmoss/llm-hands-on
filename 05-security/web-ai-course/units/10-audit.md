# 10 · 从 Source 到 Sink 的多语言审计

目标：从代码解释现象，再用测试排除猜测。先修：单元 03、05、07。

打开 `05-security/web-ai-course/audit-exercises.md`。每种语言填写：输入入口 → 类型/规范化 → 鉴权 → 危险操作 → 影响条件 → 修复 → 测试。关键词命中只是线索，没有可达调用链就不能定漏洞。安全函数名也不能证明调用参数正确。

1. 从 server.py 选 `/search` 和 `/orders`，先不看报告，写出相应的 source、sink 与缺失条件。
2. 对照 vulnerable/fixed，运行 sqli/idor；证明修改阻断异常路径且保留正常业务。
3. 阅读已有 `07-fullstack/taskboard/lib/api.ts`、auth.ts、db.ts，追踪一个真实功能；只做源代码学习，不把“看到 API”写成发现漏洞。
4. 将一小段无私密数据的代码和自己的假设送给 Ollama，请它指出需要验证的前置条件。将意见转成测试，不接受无证据的 CVE 归因。
5. 对大型项目先画模块依赖和身份传递，再按边界选函数审阅。DeepAudit 等工具作为可选工具评估，海报没有给出确定版本与配置，本文不编造安装方式。

前端加密复现：找到加密输入、密钥来源、解密位置与请求签名范围。如果密钥在 bundle 里，写出威胁模型：它可能只是协议格式或防误用，不对浏览器用户保密。不要把“会解密”与“有权调用接口”混为一谈。

产物：六语言中至少三题的调用链；一个正常反例；两条回归测试。需要运行框架时固定依赖版本，按 ADVANCED 建独立环境，不在共享系统升级全局包。
