# 学习与实验手册

每天能投入约两小时时，优先使用[第一周实操计划](week-01-plan.md)，
并填写[每日实验日志](../practice/week-01/log.md)。下面保留长期学习的阶段目标。

每天约一小时：10 分钟读代码，35 分钟修改和运行，15 分钟记录与解释。
有 Python 基础可以按 4–6 周安排，具体节奏由每阶段验收决定。

## 第 1 阶段：请求和聊天

运行第一课，写出谁是客户端、请求的 URL、messages 和 stream 的作用。
自己写第二轮请求，比较保留/移除历史。再打开 UI 观察同一逻辑如何被复用。
完成标准：不用复制例子，独立写出单轮和两轮对话。

## 第 2 阶段：控制变量

固定五个问题，对比两个模型，或两个 temperature；每次只变一项。
记录首段输出时间、总耗时、是否正确。不要只记录速度。
完成标准：能指出一次比较有哪些混杂因素，例如模型首次加载、不同答案长度。

## 第 3 阶段：文档问答

先仅检索，再生成。对同义问法、跨文档问题、无答案问题分别检查。
至少为自己的笔记准备 20 题，记录正确来源是否进入 top-k，答案是否有原文依据。
`data/eval/questions.jsonl` 提供五题格式示例，并非完整评估集。
完成标准：遇到错误能定位到资料、切块、检索、提示词或生成环节。

## 第 4 阶段：工具调用

先测试普通 Python 函数，再让模型选择工具，最后测试需要多步调用的任务。
对比工具描述变化，观察调用参数与停止原因。
完成标准：能独立增加一个只读工具，并测试参数错误和预算耗尽。

## 第 5 阶段：整合与工程

做一个笔记助手：问答附来源，需要计算时调用工具；提供网页或 API。
验证空问题、模型掉线、坏索引、未知工具和新会话。
完成标准：别人按 README 能跑通，你能说明数据和状态保存在哪里。

## 实验记录模板

```text
日期 / 代码版本：
问题与参考答案：
模型 / 参数 / 环境：
本次只改了什么：
预期：
实际回答、命中片段或工具 trace：
耗时：
失败原因与下一次实验：
```

使用 AI 辅助时，先要求提示、解释错误和检查理解，再对照参考实现。
每个阶段至少有一次关掉参考代码后重写关键流程。
