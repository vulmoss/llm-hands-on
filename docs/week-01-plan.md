# 第一周实操计划：每天 2 小时

周期：连续或累计 7 个学习日，共约 14 小时；Day 1 从实际开始学习的日期算起。
适用基础：能运行 Python，认识函数、列表、字典；其余概念在用到时补充。

**本周目标：独立写出一个带来源的笔记问答脚本，并用实验解释聊天、RAG 和工具调用的工作过程。**
本周先掌握应用的数据流；模型训练、复杂数学推导、Docker 部署和独立前端留到后续。

## 一周总览

| 学习日 | 主题 | 当天主要动手内容 | 可检查的产出 |
|---|---|---|---|
| Day 1 | 一次模型请求 | 修改请求体，独立写一次 HTTP 调用 | `day01_http.py`，请求/响应字段说明 |
| Day 2 | 多轮聊天与流式输出 | 保留/移除历史，对比完整返回与流式返回 | `day02_chat.py`，两组对话记录 |
| Day 3 | 控制变量实验 | 同模型、同问题，对比两个 temperature | 6 次结果，质量与耗时对照 |
| Day 4 | 文档与检索 | 检查片段、建立索引，只检索不生成 | 3 篇笔记，8 道题，检索记录 |
| Day 5 | RAG 质量排查 | 生成带来源答案，对比 k，分析错误 | 8 题评估表，至少一项证据充分的结论 |
| Day 6 | 工具与 Agent | 直接执行工具，再观察模型调用与停止 | 3 个任务的 trace，调用流程解释 |
| Day 7 | 整合与验收 | 独立写笔记助手，复测并演示 | `day07_assistant.py`，一周复盘 |

每天采用同样的 120 分钟节奏，下面各天按这五段安排：

| 时段 | 用时 | 做什么 |
|---|---:|---|
| 00:00–00:10 | 10 分钟 | 回忆上一天，写下今天想验证的问题 |
| 00:10–00:30 | 20 分钟 | 定向读代码、确认运行环境，只查当天需要的概念 |
| 00:30–01:30 | 60 分钟 | 实操：跑通 → 改一个变量 → 观察 → 再解释 |
| 01:30–01:50 | 20 分钟 | 对照验收标准复测，整理失败原因 |
| 01:50–02:00 | 10 分钟 | 填实验日志，记下明天的第一步 |

时间到就记录进度。选做任务仅在提前完成时进行，不叠加到两小时之外。

## Day 1：看清一次模型调用

**今天要回答：Python 发出了什么，模型服务又返回了什么？**

**前 10 分钟**：在日志画出“当前 Python 进程 → Ollama 地址 → 模型”的三步关系，
写下自己不确定的地方。

**20 分钟阅读与准备**：配置环境并执行：

```bash
llm-lab doctor

```

只读 [第一课脚本](../examples/01_direct_http.py)。找出 URL、model、messages、stream、
JSON 序列化和 response。`doctor` 同时检查生成模型与 Embedding 模型；若只是后者未安装，
先完成聊天，Day 4 前再按其提示在 Ollama 主机准备 Embedding 模型。

**60 分钟实操**：

1. 15 分钟：运行并保存一次完整请求与响应。
2. 25 分钟：复制脚本，修改提问和系统提示词，分别运行；两次不要同时改多个参数。
3. 20 分钟：暂时关掉参考文件，尝试写出自己的最小调用，再对照修正。

```bash
python examples/01_direct_http.py > .data/week-01/day01-response.txt
cp examples/01_direct_http.py practice/week-01/day01_http.py
python practice/week-01/day01_http.py
```

**20 分钟验收**：

- [ ] 能解释服务地址和模型名分别是什么。
- [ ] 能指出请求中的问题，以及响应中的最终答案。
- [ ] 改了自己的问题后能拿到回答；不是只运行未修改的例子。
- [ ] 能用自己的话说明：当前执行的是推理请求，没有训练模型。

**最后 10 分钟**：在日志贴一个请求体、一个回答和一条新理解。

## Day 3：用实验理解参数

**今天要回答：改变一个参数后，输出和耗时有没有可观察的变化？**

**前 10 分钟**：预先写出假设，例如“temperature 较高时，同题措辞变化更大”。

**20 分钟阅读**：读 [模型实验说明](../02-model/README.md)的指标表，找到
[benchmark.py](../src/llm_lab/benchmark.py) 中客户端开始计时和收到第一段文本的位置。

**60 分钟实操**：

1. 10 分钟：固定模型、题目和输出预算，并写下质量标准：解释正确、一个具体例子、不超过三句。
2. 25 分钟：做下面两组实验，每组重复三次。保留首次请求，单独标记可能的模型加载影响。
3. 25 分钟：阅读六份答案和指标，手工填写日志对照表。

```bash
LLM_TEMPERATURE=0 LLM_MAX_TOKENS=160 llm-lab benchmark '用三句话解释监督学习，并举一个具体例子。' --repeat 3 > .data/week-01/day03-temp0.json
LLM_TEMPERATURE=0.7 LLM_MAX_TOKENS=160 llm-lab benchmark '用三句话解释监督学习，并举一个具体例子。' --repeat 3 > .data/week-01/day03-temp07.json
```

**20 分钟验收**：

- [ ] 六次实验使用相同模型、问题和输出预算，仅 temperature 不同。
- [ ] 记录答案是否正确、是否遵循格式，以及首段延迟和总耗时。
- [ ] 能说明小样本只能支持本次观察，不能据此推断所有任务的表现。
- [ ] 即使“没有明显差异”，也如实记录，不为符合假设挑选结果。

**最后 10 分钟**：写一条有数据支持的结论，以及一个可能的干扰因素。
选做：已有两个模型时再比较模型大小；本周不强制增加下载和等待时间。

## Day 4：先把资料找对

**今天要回答：一个问题是怎样找到相关原文的？**

**前 10 分钟**：解释生成模型和 Embedding 模型各自的用途。

**20 分钟阅读与准备**：读 [rag.py](../src/llm_lab/rag.py) 中的 `load_chunks`、
`VectorIndex.build`、`search`，先不读生成答案部分。执行 `llm-lab doctor`，确认 Embedding 可用。

**60 分钟实操**：

1. 20 分钟：准备三篇短笔记，每篇约 200–400 字，可以是 Python、LLM、自己的学习目标。
   优先自己写；时间不够就用仓库样例并补一篇自己的笔记。
2. 15 分钟：建立索引，打开 JSON 观察 source、start、end、text、vectors 的对应关系。
3. 25 分钟：写八道题并运行检索：三题直接问事实、两题同义改写、一题组合两处资料、
   两题资料中没有答案。先写参考答案与来源，再看系统结果。

```bash
mkdir -p practice/week-01/notes
cp data/notes/lab.md practice/week-01/notes/lab.md
cp data/notes/concepts.md practice/week-01/notes/concepts.md
# 再用编辑器新建一篇 my-learning.md，只写明确的学习资料
llm-lab index practice/week-01/notes --chunk-size 300 --overlap 50
llm-lab rag '推理服务负责什么？' --retrieve-only -k 3
```

**20 分钟验收**：

- [ ] 能从命中结果回到对应文件的原文。
- [ ] 能解释字符切块、重叠和 top-k，不把字符数当 Token 数。
- [ ] 八道题都已写入日志，并标注哪些有答案、应命中哪些片段。
- [ ] 对无答案题也看到了检索结果，理解“返回了片段”不代表“片段能回答问题”。

**最后 10 分钟**：记录一个检索正确案例和一个证据不足案例。保留今天索引，供 Day 5 使用。

## Day 5：让答案有证据

**今天要回答：回答错了，是检索的问题还是生成的问题？**

**前 10 分钟**：从昨天八道题中选一题，先口述预期证据。

**20 分钟阅读**：读 `format_hits` 和 `answer_question`，找出参考片段、问题、系统提示词
如何拼接。明确 sources 是送给模型的候选证据，不是程序已验证正确的引用。

**60 分钟实操**：

1. 30 分钟：对昨天八题生成答案，逐题对照原文；给错误分类。
2. 20 分钟：选一个直接事实题和那个需要组合资料的题，各自比较 `k=1` 与 `k=3`。
   使用同一索引、模型和问题，观察实际片段与答案，不预设更大 k 更好。
3. 10 分钟：向笔记补入一个之前缺失的事实，重新构建索引并复测对应题目。

```bash
llm-lab rag '推理服务负责什么？' --json > .data/week-01/day05-answer.json
llm-lab rag '推理服务负责什么？' -k 1 --json
llm-lab rag '推理服务负责什么？' -k 3 --json
# 修改笔记后，保持与昨天相同的切块参数重建
llm-lab index practice/week-01/notes --chunk-size 300 --overlap 50
```

错误分类只需四种：资料没有答案、相关片段未检索到、证据不足却生成答案、已有证据但回答错误。

**20 分钟验收**：

- [ ] 八题都有“证据是否齐全”“答案是否正确/拒答合理”的独立记录。
- [ ] 至少一个结论能展示具体原文、检索结果和答案作为依据。
- [ ] 修改资料后确实重建索引，并能解释为什么要这样做。
- [ ] 无答案题若出现编造，记为失败，不能因为有 sources 就算通过。

**最后 10 分钟**：统计可回答题的证据命中情况，以及两道无答案题的实际表现。
选做：另建不同 chunk_size 的索引再比较；不要与今天的 k 实验同时改变。

## Day 6：看懂工具调用

**今天要回答：是谁决定调用工具，谁执行代码，结果又如何返回？**

**前 10 分钟**：画出你猜测的“问题 → 工具 → 答案”流程。

**20 分钟阅读**：读 [tools.py](../src/llm_lab/tools.py) 中的 `calculator`、`Tool`、
`default_tools`，再读 [agent.py](../src/llm_lab/agent.py) 的循环和预算判断。

**60 分钟实操**：

1. 15 分钟：直接调用普通 Python 工具，测试正常计算、除以零、不支持的单位。
2. 30 分钟：运行单次计算、单位转换、多步计算三个任务，保存并逐项检查 trace。
3. 15 分钟：把工具预算设为 1 再试多步问题；运行确定性测试确认上限逻辑。

```bash
python -c "from llm_lab.tools import calculator; print(calculator('multiply', 6, 7))"
llm-lab agent '请用计算工具算 6 乘 7。' --trace > .data/week-01/day06-calculate.json
llm-lab agent '100 公里是多少英里？' --trace > .data/week-01/day06-convert.json
llm-lab agent '计算 2 的 10 次方，假设单位是 MiB，再转换成 GiB。' --trace > .data/week-01/day06-multiple.json
LLM_MAX_TOOL_CALLS=1 llm-lab agent '计算 2 的 10 次方，假设单位是 MiB，再转换成 GiB。' --trace
python -m pytest tests/test_agent.py -q
```

普通函数直接除零可能抛异常；通过 Agent 执行时，错误会转换为工具结果。这是两层不同的职责。
达到预算的命令返回退出码 2，是预期的停止状态。真实模型也可能直接回答、不请求工具；
这种情况下不能声称已验证预算，应查看 `test_budget_counts_all_calls_in_single_response`
和 `test_repeated_tool_calls_terminate` 的确定性测试。

**20 分钟验收**：

- [ ] 能在 trace 中指出工具名、参数、执行结果和最终答案的关系。
- [ ] 对三个任务分别检查工具选择、参数、结果转述，而不是只看答案是否流畅。
- [ ] 能说明 1024 MiB = 1 GiB，与 MB/GB 的换算不同。
- [ ] 能解释执行次数限制在哪里生效，以及失败调用也占预算。

**最后 10 分钟**：修正开头画的流程图。选做：在独立脚本注册一个只读的字符计数工具。

## 卡住时如何维持进度

- **同一错误排查 15 分钟仍没解决**：记录命令、错误、已试办法，转到当天离线练习。
  日志标为“部分完成”；下一天先用前 10 分钟处理，不能把未完成的真实调用勾选通过。
- **模型回复慢**：先把单题输出预算降到 `LLM_MAX_TOKENS=96`；对比实验中各组保持同一预算。
  只做必做题，不增加模型下载。模型仍慢时先完成检索、工具函数和数据记录。
- **模型不支持工具调用**：保留返回结果，完成工具函数与 Agent 假响应测试；真实工具调用验收延期。
- **基础语法不熟**：优先补当天的列表、字典、函数、循环、`yield`，可把选做时间用于补基础。
