# 架构与取舍

## 分层

入口层：CLI / Gradio / FastAPI 负责交互、参数与错误展示。
业务层：聊天消息、RAG、Agent、基准测试，可以注入假的 client 单独验证。
适配层：OllamaClient 集中处理原生 HTTP、超时、NDJSON 和服务错误。
Settings 是不可变配置，从环境读取，也可以在测试中直接构造。

模块导入不启动服务、不构建索引、不连接模型。所有可执行入口都有显式 main 或工厂函数。

## 为什么把主线改成显式流程

原示例把框架、UI 和模型调用写在同一个文件，初学者难以定位数据在哪里变化。
新版本把框架隐藏的消息循环和检索拼接展开，先学习协议和数据，再学习高层封装。
以后添加 LangChain/LangGraph 或向量数据库适配时，应保留相同的业务验收题。

## 状态归属

| 状态 | 保存位置 | 生命周期 |
|---|---|---|
| 配置 | Settings | 当前进程 |
| CLI 历史 | interactive 局部列表 | 当前会话 |
| UI 历史 | Gradio 浏览器会话存储 | 当前浏览器，可手动删除 |
| API 历史 | 每次请求体 | 调用者自行保存 |
| 向量索引 | JSON 文件 | index 命令显式重建 |
| 工具记录 | run_agent 局部 trace | 当前任务，随结果返回 |

## RAG 索引

UTF-8 文本 → 固定字符窗口 → 批量 Embedding → 单位向量 → JSON。
保存版本、模型标识、原文来源、字符偏移和向量；加载检查维度和数值。
查询使用同一个 Embedding 模型，做点积（单位向量的余弦相似度）。
索引按模型名字识别兼容性，同名模型的权重更新无法自动检测，应主动重建。
生成提示词包含显式编号的参考片段，答案返回候选来源，引用正确性仍需评估。
JSON 全量加载、线性检索适用于小型学习数据，下一步再替换存储后端。

## Agent 预算

默认最多执行 6 个工具调用，同一轮多个请求逐个计数。
工具失败也占预算。最后一次工具返回后允许模型总结；如果再次请求工具则停止。
工具执行记录只包含可观察的参数与结果。没有任意表达式求值、动态函数加载或 shell 工具。

## 错误边界

网络/服务/协议问题转换成 OllamaError。
无效配置、空问题、坏索引和不支持的参数给出 ValueError。
工具输入/算术错误转成结构化失败结果供模型读取；程序错误不被 catch-all 隐藏。
流式响应缺少 done 标记视为失败，CLI 不把半截回答提交到下一轮历史。
不自动重试有工具执行的流程，避免未来接入有副作用工具时重复执行。

## 测试层次

1. 确定性测试：历史、索引排序、参数、单位、调用预算。
2. 协议测试：模拟 HTTP 响应，检查请求体、流式分帧和错误。
3. 入口测试：CLI 退出码、API 校验、网页回调。
4. 真实环境验收：doctor → ask → index/rag → agent → ui。

前三层不需要实际模型。第四层才能验证服务版本、模型兼容性和真实质量。

## 固定安全评估

`security_eval.py` 复用 RAG 业务函数。每个样例、每次重复都有独立内存索引与新对话，
以显式片段为输入，记录模型设置、数据/代码摘要、检索来源、回答和启发式判分。
输入校验可完全离线运行；生成结果标注实际 Ollama 客户端或测试替身，二者不能混作模型成绩。

Promptfoo 配置从 HTTP API 进入，离线契约测试通过 FastAPI TestClient 复核请求形状及 JS 断言。
真实 CLI、模型和服务兼容性仍要在实际环境验收。实验清单只生成导航，不执行其中的命令。
